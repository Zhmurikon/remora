# План ручной проверки страниц сайта

Документ задаёт порядок совместной проверки production-сайта «Запоминальни». Проверка идёт
не по всему продукту сразу, а по одной странице или одному связанному сценарию за шаг. Для
каждого шага отдельно фиксируются визуальный результат, функциональность, SEO и скорость.

Основные адреса:

- публичный сайт — `https://zapominalnya.ru`;
- кабинет — `https://zapominalnya.ru/app`;
- административная панель — `https://admin.zapominalnya.ru`.

Учётные данные и секреты в этот документ не записываются.

## 1. Распределение проверки

| Часть | Исполнитель | Результат |
| --- | --- | --- |
| Ручной визуальный отсмотр | Владелец продукта | `OK` либо описание визуального дефекта |
| Функциональный сценарий | Codex, при необходимости вместе с владельцем | Пройденные действия и фактический результат |
| SEO | Codex | Проверка метаданных, индексации, ссылок и структурированных данных |
| Скорость | Codex | Медианные результаты трёх запусков и найденные узкие места |

Для кабинета и административной панели SEO-проверка означает подтверждение того, что закрытые
страницы не попадают в sitemap и поисковый индекс. Полный on-page SEO-аудит нужен только для
публичных индексируемых страниц.

## 2. Порядок одного шага

1. Codex уточняет точный URL, необходимую роль и тестовые данные, проверяет доступность страницы.
2. Владелец визуально осматривает страницу и сообщает `OK` либо перечисляет замечания.
3. Codex проходит функциональный сценарий страницы, включая ошибки и граничные состояния.
4. Codex выполняет SEO-проверку либо подтверждает корректное исключение страницы из поиска.
5. Codex снимает показатели скорости на мобильном и настольном профилях.
6. Результат заносится в журнал этого документа. Дефекты получают приоритет и отдельную задачу.
7. К следующей странице переходим после фиксации результата текущей. Исправления можно собрать
   в отдельный этап, если дефект не блокирует дальнейшую проверку.

## 3. Общий чек-лист страницы

### 3.1. Визуальный отсмотр

- ширины 390, 768 и 1440 px;
- светлая и тёмная темы, если тема доступна на странице;
- масштаб браузера 100% и 200%;
- отсутствие горизонтальной прокрутки, обрезания текста и наложения элементов;
- корректные логотип, шрифты, цвета, изображения, формулы и блоки кода;
- состояния загрузки, пустых данных, ошибки и длинного содержимого;
- видимый фокус при работе с клавиатуры;
- цели нажатия не меньше 44 px на мобильном;
- отсутствие заметных скачков макета при загрузке.

Основной браузер — актуальный Chrome. Для критичных публичных и учебных сценариев после
основного прохода выполняется контрольная проверка в Firefox и Safari.

### 3.2. Функциональность

- все ссылки, кнопки, формы и интерактивные элементы;
- валидные и невалидные данные формы;
- прямое открытие URL, обновление страницы, переходы «Назад» и «Вперёд»;
- загрузка, пустое состояние, серверная ошибка и потеря сети;
- права гостя, владельца и чужого пользователя;
- защита от повторной отправки действия;
- сохранение введённых данных и восстановление незавершённого сценария, где это требуется;
- работа с клавиатуры без мыши.

### 3.3. SEO

Для индексируемой страницы:

- ответ `200`, отсутствие запрета индексации, присутствие в sitemap;
- уникальные `title`, `description` и один основной `h1`;
- корректный абсолютный canonical на `zapominalnya.ru`;
- Open Graph и Twitter Card с рабочим изображением;
- валидный и согласованный с видимым содержимым JSON-LD;
- осмысленные внутренние ссылки, хлебные крошки и `alt` у содержательных изображений;
- отсутствие битых ссылок, цепочек редиректов и смешанного HTTP/HTTPS;
- корректный результат без JavaScript там, где содержимое должно индексироваться;
- мобильная версия содержит то же основное содержимое, что и настольная.

Для закрытой страницы:

- URL отсутствует в sitemap;
- поисковый робот не получает закрытое пользовательское содержимое;
- гостевой запрос не открывает данные и приводит к ожидаемому входу либо отказу;
- административный домен не индексируется.

### 3.4. Скорость

Для каждой контрольной страницы выполняются три запуска с холодным кэшем на мобильном и
настольном профилях; в журнал записывается медиана. Лабораторные данные Lighthouse сверяются
с полевыми данными CrUX, если они доступны.

Контрольные значения:

- LCP — не больше 2,5 с;
- INP — не больше 200 мс по полевым данным;
- CLS — не больше 0,1;
- TTFB — желательно меньше 800 мс;
- Lighthouse Performance публичной страницы — целевой результат не ниже 95; результат ниже
  90 требует отдельного разбора;
- Lighthouse SEO публичной страницы — не ниже 95.

Для SPA-страниц кабинета отдельно проверяются первый вход, повторная навигация и тяжёлое
интерактивное состояние. Лабораторный TBT используется только как диагностический показатель,
а не как замена INP.

## 4. Необходимые состояния данных

Перед началом соответствующих этапов должны быть доступны:

- гость без сессии;
- новый пользователь с пустой библиотекой;
- пользователь Free с курсами, наборами и достигнутым лимитом создания;
- пользователь Plus с собственным и сохранённым содержимым;
- владелец опубликованного курса;
- преподаватель с классом и заданиями;
- ученик с назначенным заданием;
- два пользователя для битвы;
- администратор;
- публичный курс с текстом, изображениями, формулами, кодом, статьями и карточками.

## 7. Формат дефекта

Каждое замечание фиксируется в следующем виде:

```text
ID: WEB-CHECK-001
Приоритет: критичный | высокий | средний | низкий
URL и роль:
Окружение: production, браузер, устройство, ширина
Шаги воспроизведения:
Ожидаемый результат:
Фактический результат:
Артефакт: скриншот, видео, Lighthouse JSON или лог без секретов
Повторная проверка:
```

Критичный дефект означает потерю данных, нарушение доступа, невозможность войти или пройти
основной сценарий, недоступность сайта либо блокировку индексации всего публичного контура.
Высокий — сломанный ключевой сценарий отдельной страницы, неправильный платёжный переход,
существенная мобильная проблема или плохие Core Web Vitals на важной странице.
