# Редакционные подборки E6A

## Что реализовано

Публичные маршруты `/podborki` и `/podborki/{slug}` в `apps/web`: список подборок,
описание и вводный текст, упорядоченные ссылки на оригиналы курсов, пояснения редакции.
Подборки не создают копий материалов и не меняют прогресс обучения. Входы — главная,
блог и каталог. Новый интерфейс продолжает палитру и свободную композицию главной.

Редакция файловая, как у блога; отдельной CMS и роли редактора в кабинете нет.
Миграции БД не нужны. Источник — `apps/web/src/content/collections.ts`.

## Как опубликовать подборку

1. Выбрать реальные опубликованные курсы, доступные в общем каталоге.
2. Добавить объект `EditorialCollection`: уникальный латинский `slug`, название,
   описание, вводный текст, даты `publishedAt`/`updatedAt` в ISO-формате, цветовую тему.
3. Заполнить `courses`: от 1 до 50 уникальных UUID курсов и непустое пояснение `note`
   для каждого. Порядок в массиве — порядок на странице. UUID берётся из API курса;
   название, slug, автор и счётчики не копируются в редакционный файл.
4. Проверить содержание и права доступа. Перевести `status` из `draft` в `published`.
5. Выполнить тесты, сборку и выпуск. Изменения файлов, включая снятие подборки с публикации,
   требуют пересборки сайта. Будущая дата — защита от раннего выпуска, не планировщик.

Черновики, будущие даты, подборки без выбранных UUID и неизвестные адреса возвращают 404;
они отсутствуют в списке и sitemap. Черновики не являются защищённым хранилищем:
секретов и приватных учебных текстов в редакционных файлах быть не должно.

На момент реализации заполненных подборок нет. Темы «К первому зачёту» и «Языки понемногу» —
неопубликованные заготовки без курсов. Публичный раздел честно сообщает, что подборки готовятся,
и предлагает каталог. Отбор курсов остаётся отдельной редакционной задачей.

## Доступность оригиналов

`GET /api/v1/search/courses/selected?ids=<uuid>&ids=<uuid>` принимает от 1 до 50 UUID.
Сервис использует существующую проверку каталога в PostgreSQL, без Meilisearch.
Возвращается только `CourseSearchItem`: без теории, карточек и приватных полей.
Дубликаты устраняются, порядок сохраняется, отсутствующие и недоступные UUID пропускаются.

Исключаются черновики, публикации «по ссылке», заблокированные и пустые курсы,
удалённые/заблокированные авторы, удалённые либо принадлежащие другому автору вложенные наборы.
Знание UUID и присутствие в редакционном файле не дают дополнительных прав.

Страница подборки — динамический SSR. Запрос использует `cache: no-store` и тайм-аут;
API также отвечает `Cache-Control: no-store`. React `cache` дедуплицирует загрузку
страницы и метаданных только в пределах одного SSR-запроса. Снятый с публикации курс
и его редакционное пояснение исчезают при следующем открытии страницы. Уже открытая
страница не обновляется автоматически; доступ к самому курсу проверяет его API.

Если все курсы закрыты, остаются описание подборки и пустое состояние со ссылкой на каталог.
При сбое API показывается ошибка с повтором, без устаревших данных и без ложного «курсов нет».

## SEO

- Canonical, Open Graph `website`, Twitter Card с общей OG-картинкой.
- JSON-LD `CollectionPage`, `ItemList`, `BreadcrumbList`; курс и его название берутся
  только из доступного результата API. Порядок совпадает с HTML.
- Пустая подборка или ошибка API получают `noindex, follow`; при ошибке JSON-LD не выдаётся.
- В sitemap попадают только опубликованные подборки хотя бы с одним доступным курсом.
  Дата изменения — редакционная `updatedAt`. При недоступном API URL подборок пропускаются.
- Пустой раздел без опубликованных подборок — `noindex`, вне sitemap.
- На маршруте нет верхнего `loading.tsx`: ранний streaming не должен превращать 404
  неизвестной подборки в HTTP 200. Навигация использует обычные ссылки и полный SSR.
- Запрет индексации тестового окружения не меняется.

## Проверки и выпуск

Автотесты охватывают порядок, дубликаты, ограничения запроса, закрытые оригиналы,
снятие публикации, черновики, даты, 404-контракт, ошибки, экранирование, метаданные и sitemap.
Заполненный интерфейс проверяется на тестовых данных, которые не входят в редакционные файлы.

Проверено 18.09.2026: 55 тестов web (16 новых), все 349 фронтенд-тестов, 20 серверных
тестов поиска/прав, ESLint, TypeScript, ruff/mypy и production-сборка Next.js.
HTTP: список 200, оба черновика и неизвестный адрес 404, пустой раздел noindex и вне sitemap.
Браузер: светлая/тёмная темы, клавиатурный фокус, ширины 320/375/768/1440 px,
landscape 844 × 390, отсутствие горизонтального скролла, цели нажатия от 44 px.
Навык UI/UX использован для проверки доступности и адаптивности; существующие токены
и согласованное направление главной имеют приоритет над общими рекомендациями.

Известные предупреждения: сетевой шрифт OG иногда не загружается при сборке (сборка успешна,
задача уже есть в плане); общий `format:check` отмечает не изменённый этим срезом файл
транскрипции `apps/web/src/app/rasshifrovka/api/access/route.ts`. Изменённые файлы проходят Prettier.

Срез реализован локально; на сервер в рамках этой задачи не выкладывался.
Перед публикацией нужен редакционный отбор реальных курсов. Следующий технический срез E6A —
производительность и локальный шрифт OG, затем постмодерация.
