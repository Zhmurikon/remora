# Классы: три концепта

Этап 1, 18 ноября 2026. Страница `/app/classes`. Владелец выбрал вариант Б и разрешил реализацию. Готовый навигатор, движение и результаты проверок описаны в [отчёте реализации](../implementation.md).

- [А — классы по ролям](a.png): обе роли на одном экране, действия стоят у соответствующей группы. Удобно совмещать преподавание и обучение; длинный список увеличивает прокрутку.
- [Б — навигатор классов](b.png): список и предпросмотр названия, описания и роли. Ближе всего к текущим «Материалам», но добавляет промежуточный выбор перед открытием.
- [В — простой список](c.png): переключение роли, широкие строки и непосредственный переход. Рекомендация для этой страницы: список содержит немного полей, отдельная панель предпросмотра обычно не нужна.

PNG имеют одинаковый размер 1440 × 1302. Верх — экран кабинета; нижняя полоса — отдельные состояния, она не является частью будущей страницы. Данные вымышленные учебные, одинаковые для всех вариантов: три активных преподавательских класса (в том числе один с ролью ассистента), один архивный и один ученический. Счётчик «Преподаю 4» включает архив. Исходники статических иллюстраций — `index.html`, `concepts.css`, `concepts.js`; параметр `?variant=a|b|c`. Это макеты, кнопки не подключены к API.

Каркас, синие чернила и бумажная поверхность взяты из работающих `AppLayout.tsx`, `dashboard.css`, `materials.css` и актуальных `--rm-lecture-*` токенов. Синий знак используется напрямую из `apps/web/public/lecture-demo/remora-icon.png`, как в текущем бумажном каркасе; знак не перерисовывался. Небольшая иллюстрация пустого состояния — существующий `course-books.webp`. Историческая бирюзовая палитра `design.md` не использована. Производственные файлы не менялись.

## Функциональный контракт из кода

Источники: `apps/app/src/pages/ClassesPage.tsx`, её компонентные тесты; `apps/api/app/schemas/classes.py`, `services/classes.py`, `services/class_permissions.py`, `services/entitlements.py`, `repositories/classes.py`.

| Сценарий | Подтверждённое поведение |
| --- | --- |
| Список | `GET /api/v1/classes`; только активное членство, архивные классы тоже возвращаются. Сначала неархивные, затем по дате создания от новых к старым. |
| Роли | «Преподаю» объединяет `teacher` и `assistant`; «Учусь» — `student`. Если есть только ученические классы, текущая страница автоматически открывает «Учусь». В А соответствующая непустая группа становится первой. |
| Поля списка | Название, описание, собственная роль, `archived_at`, даты, `requires_approval`, `join_code`. Нет счётчиков учеников, заданий, прогресса, дедлайнов или `is_read_only`. Код не выводим в строку списка. |
| Создание | Название после `trim`, максимум 160 символов; текущая форма отправляет `description: ''`, `requires_approval: false`. Успех обновляет список и открывает `/app/classes/:id`. Пустое название не отправляется. |
| Вступление | Код 8–12 символов, пробелы по краям убираются, регистр приводится к верхнему. `active` открывает класс; `pending` показывает подтверждение заявки. Ожидающий класс ещё не входит в список, отдельного API списка заявок ученика нет. |
| Пригласительная ссылка | `/app/classes/join?code=…` показывает код и явное подтверждение вступления. Код сам по себе не запускает POST. |
| Ошибки | Ошибка списка с повтором; ошибка создания/вступления рядом с формой. Несуществующий или архивный код не принимается. Ограничения создания класса/приёма учеников берутся из Entitlements, не вычисляются по названию тарифа. |
| Переход | `/app/classes/:id`: преподаватель и ассистент получают преподавательский экран, ученик — свои задания и материалы. Есть возврат ко всем классам. |
| Права преподавателя | Редактирование класса, управление участниками и приглашениями; материалы, задания, отчёты. |
| Права ассистента | Материалы, задания и отчёты. Нет управления участниками, приглашениями и редактирования класса. |
| Права ученика | Доступ к классу, материалам и собственным заданиям; переход в нужный режим обучения. Нет чужих отчётов. |
| Просмотр без создания | `is_read_only` и `can_create_assignments` доступны в detail. Материалы и обучение сохраняются. В макетах сообщение показано только как состояние после открытия, не как недостоверный статус строки списка. |

Внутри преподавательского класса уже существуют приглашение, одобрение заявок, добавление своих наборов, создание задания с целью и дедлайном, матрица прогресса, детализация ученика, ошибки карточек и XLSX. Внутри ученического — задания с прогрессом и сроками, отложенное открытие, переход в нужный учебный режим и наборы класса. Концепты сохраняют вход в эти экраны, не переносят их статистику на список.

## Решения для последующей реализации

- Сохранять полные названия. Короткие описания показывать целиком, длинные раскрывать отдельной кнопкой «Полное описание», без вложенной кнопки внутри ссылки. В Б описание находится в предпросмотре.
- «Архив» в макетах — предлагаемая группировка уже возвращаемых `archived_at`, не новая операция архивирования, удаления или восстановления. Эти действия на список не добавлены.
- Создание и вступление разворачиваются рядом с вызвавшим их действием; одна форма открыта за раз. Назад/закрытие возвращает фокус к триггеру. Отправка, успех и ошибка имеют отдельные состояния; ошибка сохраняет введённый текст.
- В Б выбранная строка открывает описание, «Открыть класс» — существующий маршрут. В А и В строка сразу открывает класс. На телефоне Б становится последовательностью список → описание → класс с возвратом, А и В остаются одноколоночными.
- При реализации обязательны клавиатура, видимый фокус, подсказки компактных иконок на hover/focus, цели от 44 px, ширина от 320 px, обе темы и reduced motion. Статические изображения не считаются проверкой доступности будущей реализации.
- Следующий этап после выбора: проработать и показать движение; затем внедрить выбранную композицию, подключить движение и проверить действия и переходы.

## Найденные несоответствия

1. `TeacherClass` показывает кнопку приглашения ассистенту, хотя серверная матрица разрешает `manage_members` только преподавателю. Исправлено в реализации Б: приглашение показывается только преподавателю.
2. Подтверждение `pending` в `JoinClassPage` сейчас хранится в переменной ошибки и выводится красным. В реализации Б это нейтральный успешный статус; доступ к классу не обещается до одобрения.
3. Нельзя выводить режим «Только просмотр» в списке из существующего `ClassroomOut`: такого поля в нём нет. Для этой задачи сохраняем сообщение в detail; расширение API не требуется.

## Проверки этапа

- В браузере с изолированными API-фикстурами проверены текущие создание → класс, вступление с `active` → класс, `pending` → сообщение без перехода, нормализация кода, автоматический выбор ученической вкладки и открытие «Моих заданий».
- Все три PNG визуально просмотрены; изображения и токены загружаются, длинные названия не обрезаются, ширина документа равна 1440 px. Результаты последующих проверок реализации находятся в [отчёте](../implementation.md).
- Правила ролей и ограничения сверены по серверному коду. API-фикстуры не доказывают работу сервера или платёжных квот; здесь проверялись фронтенд-переходы действующей страницы.
