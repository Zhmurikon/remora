# Внутренние экраны классов

По одному концепту каждого оставшегося экрана, в продолжение выбранного варианта Б списка классов. Все четыре макета утверждены владельцем 18 ноября 2026 года. Реализация и результаты проверок описаны в [отчёте](implementation.md). Исходники концептов сохранены как визуальный ориентир.

| Экран | Изображение | Основная композиция |
| --- | --- | --- |
| Преподаватель / ассистент | [teacher.png](teacher.png) | Заявки, журнал учеников, форма задания, материалы и частые ошибки |
| Ученик | [student.png](student.png) | Задания по ближайшему сроку, прогресс, продолжение и материалы справа |
| Отчёт по ученику | [report.png](report.png) | Задания, фактический результат относительно цели и последняя активность |
| Приглашение | [invitation.png](invitation.png) | Код, явное подтверждение вступления и объяснение одобрения |

Во всех изображениях сохранены оболочка кабинета, бумажный фон, синие акценты, антиква заголовков и тонкие разделители. Основные элементы управления — от 44 px. Внизу каждого изображения приведены состояния и правила доступа; это пояснения к концепту, а не дополнительная панель рабочего интерфейса.

## Основание и границы

Проверены маршруты `apps/app/src/App.tsx`, реализации `TeacherClass`, `StudentClass`, `StudentReportPage`, `ClassInvitation` в `apps/app/src/pages/ClassesPage.tsx` и права в `apps/api/app/services/class_permissions.py`. Источник стиля — выбранный вариант Б и уже реализованный `ClassNavigator`.

- Ассистент использует композицию преподавателя без приглашения и приёма заявок. Отдельного пятого экрана не требуется.
- Формы создания задания и добавления набора остаются встроенными в страницу. Новые модальные окна и вкладки не вводятся.
- Форма задания сохраняет название, набор, три типа цели, значение и необязательный срок. При реализации ограничения значений и доступность действий берутся из существующих контрактов.
- Матрица сохраняет четыре статуса и числовой результат. Имя ученика ведёт к отдельному отчёту. Выгрузка XLSX и приглашение сохраняют существующее поведение.
- Частые ошибки — только агрегат класса; ответов конкретного ученика в макете нет. В рабочей версии сохраняется текущий предел десяти карточек, в концепте приведены две строки.
- Задания ученика сохраняют выбор режима обучения, срок, открытие в будущем и возможность продолжить после дедлайна. Полоса показывает достижение цели, а не абстрактный процент активности.
- Отчёт не добавляет оценки, рейтинги или статистику посещений. Название класса в шапке — предлагаемый контекст; при реализации его можно получить из существующего запроса класса. Ученик не получает доступ к чужим отчётам.
- До вступления название класса не показано: текущая ссылка содержит только код. Никакого автоматического POST при открытии страницы. После ответа API — переход в класс либо ожидание одобрения; ошибки показаны отдельно.
- Режим просмотра сохраняет материалы, учеников и прежние задания. Доступность новых действий определяется существующими правами и Entitlements.

Имена, учебные материалы, числа, даты и код — демонстрационные. Данные прогресса Анны согласованы между журналом, экраном ученика и личным отчётом. Макет ничего не отправляет в API.

## Просмотр и проверка

Открыть `index.html?screen=teacher`, `?screen=student`, `?screen=report` или `?screen=invitation`. Исходники: `screens.js`, `screens.css`; палитра импортируется из общих токенов, знак — существующий `remora-icon.png`.

PNG сняты в Chromium при ширине 1440 px, масштаб 1. Все четыре изображения просмотрены. Проверены загрузка ассета, отсутствие горизонтального переполнения и ошибок JavaScript. Эти исходники остаются статическими desktop-концептами. Интерактивность, адаптивные версии и тёмная тема реализованы отдельно в приложении; см. [отчёт о реализации](implementation.md).
