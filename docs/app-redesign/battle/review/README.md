# Битва 1×1: реализация и локальная проверка

18 ноября 2026. Область изменений: `BattlePage.tsx`, `battle.css`,
`features/battle/useBattleAnswer.ts`, тесты страницы. Общие компоненты, сервер, схема API
и правила обучения не изменены.

Обновлены создание приглашения, число вопросов и направление, вход по ссылке, два места
в комнате, готовность и загрузка изображений, отсчёт, вопрос, ожидание соперника, сравнение
точности и времени, разбор, реванш, выход, истёкшая и отменённая комнаты.

Копирование подтверждается; при отказе браузера ссылка выделяется для ручного копирования.
Ошибки готовности, выхода, создания, вступления, реванша и результата остаются рядом с действием.
Повтор создания/реванша использует прежний request_key. Ответ записывается на устройстве до
отправки и повторяется с прежним client_answer_id. Хранилище разделено по пользователю и комнате.
После перезагрузки текущий вопрос определяется серверным answered_count. Фоновая сетевая
ошибка сохраняет экран и явно предупреждает, что время не остановилось.

## Проверки

- 17 тестов страницы: создание и повтор, ограничения набора, вход, третий участник,
  доступ участника по старой ссылке, отказ clipboard, готовность, двойные клики,
  восстановление вопроса/ответа, сбой polling, общий финиш, истечение/отмена,
  ничья, ошибка разбора/реванша, выход и клавиатура. Отдельный тест проходит все вопросы через Tab/Enter и проверяет фокус заголовка нового вопроса и результата.
- ESLint изменённых TS-файлов, typecheck кабинета и production-сборка прошли.
  Сборка сообщает существующие предупреждения MediaInfo/pyodide и крупных chunks.
- Три серверных теста `tests/test_battles.py` прошли в отдельной локальной БД
  `battle_redesign_test` и отдельной Redis DB 14. Тестовая БД после проверки удалена.
- Реальная игра двух временных аккаунтов в независимых браузерных контекстах, третий аккаунт
  проверяет запрет входа. Полный протокол — `live-checks.json`.
- Живой прогон включает буфер обмена и его отказ, одинаковые вопросы, готовность/отсчёт,
  клавиатуру, отключение сети, перезагрузку с неотправленным ответом, общий результат,
  личный разбор, реванш, отмену и подтверждение выхода, неправильное приглашение.
  Отдельная реальная игра обоими участниками пройдена через Tab/Enter с проверкой фокуса каждого вопроса и результата (`keyboard-live.json`).
  Второй синхронный проход завершился настоящей ничьёй. Просроченный подписанный токен также проверен через локальный API (`extra-checks.json`). Изображение загружено через локальное
  хранилище; формулы отображаются общим CardContent. FSRS после битв остался без изменений.
- Дополнительно состояния waiting/active/finished/expired/cancelled проверены с API-фикстурами
  на основе реальной комнаты: обе темы, 320 и 1440 px. Горизонтального переполнения нет,
  кнопки от 44 px. Отдельно проверены текст 200%, фокус и reduced motion (`layout-checks.json`).
  Имена Мария/Алексей и ничья на снимках матрицы — демонстрационные данные. После ревью участники переходят в отдельные строки при нехватке места. Тема выбирается через сохранённую настройку оболочки, чтобы логотип и CSS соответствовали друг другу.
- Детектор не сообщил обязательных нарушений. Advisory по размерам и радиусам относится
  к устаревшей шкале sidecar; использованы значения живого SetPage и текущей спецификации.

## Исправления после независимого ревью

Фокус переносится на заголовок при смене шага, без озвучивания каждого обновления часов.
При нехватке ширины участники располагаются отдельными строками; это сохраняет читаемые имена
на 320 px и при тексте 200%. Стрелка возврата и раскрытие разбора используют SVG.
Снимки тёмной темы пересняты со штатной настройкой темы оболочки.

Независимый reviewer подтвердил закрытие четырёх перечисленных исправлений; verdict `ship` относится к этому пакету исправлений. Проверка соответствия действующему оформлению — `design-conformance.md`.

Временные три аккаунта, два изображения и связанные учебные данные удалены из локальной БД и хранилища.

## Ограничения

Локальный прогон не заменяет отдельную проверку двух участников на dev-сервере.
Серверный пункт TODO остаётся открытым. Push и деплой не выполнялись.
Состояния expired/cancelled в визуальной матрице контролируются фикстурами;
права, идемпотентность и отсутствие изменения FSRS дополнительно покрыты серверными тестами.
