# Исправления после проверки практики

18 ноября 2026 года. Все перечисленные в [первичной проверке](release-check-2026-11-18.md)
недочёты устранены. Проверки выполнены локально; push и публикация не выполнялись.

## Изоляция аккаунтов

- Ключи локального прогресса и офлайн-очереди содержат ID пользователя.
- Синхронизация, отложенные сохранения, сброс и результаты Python-исполнителя привязаны
  к владельцу и конкретной сессии. Выход отменяет запросы; поздний ответ не изменяет данные
  нового аккаунта. Повторный вход в тот же аккаунт также создаёт новую сессию.
- Очередь А не мешает синхронизации Б и возобновляется только после возвращения А.
- Отменённый запрос не повторяется после обновления токена. Запоздалый refresh не меняет
  новую сессию; токен другого владельца из общей cookie соседней вкладки отклоняется.
- Старые записи localStorage без владельца остаются нетронутыми, но не импортируются
  автоматически. Надёжно установить их владельца невозможно. Серверный прогресс
  восстанавливается обычной синхронизацией.

Добавлены регрессии для разделения черновиков и очередей, гостевого режима, повторного
входа, поздних GET/PUT/DELETE и результатов worker, отмены повтора запроса и смены
аккаунта во время refresh.

## Линтер, форматирование и время тестов

Проверены объявления браузерных глобальных переменных в двух скриптах макетов классов:
три ошибки `no-undef` устранены. Отформатирован 31 файл из первичного отчёта.

Первый импорт `scipy.stats`, `matplotlib.pyplot` и инициализация графического backend
перенесены в подготовку тестовой среды. На подготовку выделено 120 секунд; лимит
отдельного теста остаётся 5 секунд, лимит исполнения пользовательского кода — 3 секунды.
Общий запуск тестов выполняет пакеты последовательно, максимум с двумя workers внутри
пакета, чтобы несколько пулов одновременно не перегружали машину CI.

В Chromium проверена производственная сборка с `/app/` и локальным Docker API:

- вход, каталог, редактор, реальное выполнение Python через worker/WASM, успешная
  проверка решения и сохранение статуса;
- А сохраняет решение, Б получает собственный пустой прогресс и создаёт свой черновик,
  возвращение в А восстанавливает его решение; данные обоих аккаунтов сверены с API;
- ошибка PUT 503 оставляет очередь А локально; вход Б её не отправляет, возвращение
  А успешно отправляет её владельцу;
- смена cookie на Б в соседней вкладке и ответ 401 на запрос А не приводят к повторной
  отправке с токеном Б;
- старые записи без владельца сохранены и не импортированы, ошибок страницы и
  загрузки ресурсов нет. Временные проверочные аккаунты удалены.

Backend не менялся; полный pytest и серверный выпуск в эту проверку не входили.
Результат относится к указанному снимку исправлений, а не ко всем параллельным
незакоммиченным изменениям общей рабочей копии.
