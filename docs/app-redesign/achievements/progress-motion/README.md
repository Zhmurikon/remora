# Карточки коллекции — реализация и движение

Выбранный вариант А подключён к верхней сводке достижений. Все мини-карточки создаются из `total_count`; первые `unlocked_count` заполнены. Это счётная шкала, а не кнопки отдельных наград. Доступная роль `progressbar` сохраняет числовые значения; декоративные элементы скрыты от скринридера.

[Анимация](preview.gif) — снимки реальной CSS-анимации из локального браузера. В записи повторяется цикл для просмотра; в приложении анимация однократная, без фонового движения. [Светлый экран](light-1440.png), [тёмный экран](dark-1440.png), [телефон](dark-320.png).

При загрузке полученные карточки переворачиваются слева направо: 440 мс на карточку, шаг 24 мс, максимальная задержка 360 мс. Число и процент не считают от нуля и не ждут завершения. При росте прогресса переворачиваются только новые заполненные элементы; стабильные React-ключи сохраняют прежние узлы. Используются CSS keyframes без новых библиотек и таймеров. В режиме уменьшения движения конечное состояние показывается сразу.

На широком экране сводка высотой 66 px. До ширины контейнера 53 rem шкала переносится под счётчик и процент; до 33 rem карточки располагаются по десять в ряд. Большие карточки достижений по-прежнему идут по четыре на широком экране. Серый фильтр применяется только к рисункам неполученных наград.

Проверки:

- Семь тестов страницы и уведомления. Проверены пустая коллекция, переход 0 → 1 → 3 из 3, сохранение DOM-узлов, доступные значения и 100%, прежние ошибки, загрузка и статусы.
- ESLint двух целевых TSX-файлов и Prettier трёх изменённых исходников прошли.
- В браузере проверены обе темы на 320, 390, 768, 1024, 1280, 1440 и 1920 px; 20 элементов, 10 заполненных, без горизонтального переполнения. В reduced motion нет анимации; обычный режим запускает десять однократных переворотов. При временном изменении одиннадцатого элемента появляется ровно одна новая анимация, прежние сохраняются. Подмена только в DOM для проверки, серверные награды не менялись. [Результаты](checks.json).
- Общая проверка TypeScript не прошла из-за ошибок вне достижений: `BillingLimitDialog.test.tsx:46` (`fireEvent.cancel`) и `TranscriptionsPage.tsx:924,928` (`limit` может быть undefined). Эти параллельные изменения не исправлялись в данной задаче. Ошибок целевых файлов проверка не сообщила; полная сборка не объявляется успешной.
