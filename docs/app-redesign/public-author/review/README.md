# Публичный профиль автора — проверка 18.11.2026

Обновлён `/avtor/[username]` в существующем направлении каталога и публичного курса: бумажный фон, заголовок Georgia, синие ссылки, тонкие разделители. Подключены существующие `LandingHeader` и футер с утверждённым логотипом через **новый локальный layout маршрута автора**. Общие layout, CSS, токены, каталог и публичный курс не изменялись.

Профиль показывает публичные имя, username, аватар и дату регистрации. При отсутствии или ошибке фотографии остаётся инициал; при отсутствии имени заголовком становится username. Сначала видны курсы автора: название, темы, описание до трёх строк, число карточек и сохранений, языки и дата обновления. Вся строка ведёт к действующему курсу; фокус видим по её контуру. Ниже сохранён ранее реализованный `AuthorAchievements` без изменения его файлов, пяти показателей и списка полученных наград. Якоря позволяют перейти к курсам и достижениям.

## Контракт и приватность

Проверены `AuthorProfile`, `AuthorService`, репозиторий авторов и фактический публичный ответ локального API для `yuriy`. На момент проверки он содержит один курс, 3 сохранения, 2 лайка, 105 изученных карточек, серию 0 дней и две награды. Это исходные данные API, не вычисленные или вымышленные показатели интерфейса. Email, настройки, биография, подписчики и рейтинг не добавлены. `id` автора не показывается.

Сервер исключает недоступных авторов и непубличные курсы; **аккаунт без публичных курсов возвращает 404**. Это поведение сохранено: проверен существующий локальный аккаунт без публикаций, HTTP 404 и `noindex`. Как и прежде, прямой запрос такого профиля получает стандартный экран 404 Next.js. Пустой список внутри успешного ответа остаётся защитным состоянием и проверен отдельно на фикстуре. API, права доступа и правила публикации не менялись.

Успешные metadata, canonical, Open Graph, Twitter, JSON-LD `ProfilePage`, SSR и существующий кэш 60 секунд сохранены. HTML без выполнения JavaScript содержит имя и курсы. Ошибка API не превращается в пустой профиль или 404. Локальная граница ошибки предлагает каталог и повтор; повтор обновляет серверный компонент через `router.refresh()` и сбрасывает границу ошибки.

## Проверки

- 19 тестов: 12 страницы, 2 аватара/ошибки, 5 публичного кэша. Проверены отсутствие необязательных полей, пустой ответ, 404, 500/503, сетевой сбой, публичные поля, экранирование текста, метаданные, восстановление фотографии и вызов серверного повтора.
- TypeScript публичного сайта, ESLint области автора и Prettier — без ошибок.
- Production-сборка публичного сайта выполнена в отдельной временной копии, чтобы не затрагивать HMR и сборки соседних чатов.
- Реальный локальный профиль: обе темы при 320, 390, 768, 1024, 1440, 1920 и 3840 px. Дополнительно 320 px с текстом 200% в обеих темах. Переполнения нет; цели ссылок профиля от 44 px. Локальный класс футера устраняет его переполнение при увеличении текста, не затрагивая другие страницы.
- Три состояния ответа — пустой список, отсутствие необязательных полей, длинные имя/название/теги/описание и три курса — на изолированном production-стенде с API-фикстурами. Обе темы, 320 и 1440 px: 12 сочетаний без переполнения. Фикстуры не записывались в БД.
- Проверены клавиатурный фокус, переход по курсу клавишей Enter, переход в каталог, якорь списка курсов. Отдельно — `prefers-reduced-motion`.
- На production-стенде проверена ошибка 503 и успешный повтор после восстановления ответа API.

Реальные учебные данные не изменялись. Серверные операции, публикация и push не выполнялись. Исходные незакоммиченные изменения страницы с подключением `AuthorAchievements` сохранены; его компоненты и ассеты не входят в новые изменения этой задачи.
