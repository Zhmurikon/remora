# Публичный самостоятельный набор

Проверено локально 18 ноября 2026 года. Работа ограничена `apps/web/src/app/nabor/[slug]/`.

## Результат

Страница продолжает оформление публичного курса: бумажный фон, антиква в заголовках,
синий акцент, тонкие разделители. В шапке используется существующий `FishMark`.
Добавлены ссылка на доступный профиль автора, каталог, сводка количества и доступа, якорь к карточкам,
пустое состояние и переход в кабинет после подтверждения прав сервером.

Обе стороны карточки остаются видны: две колонки на широком экране и последовательные
блоки на телефоне. Сохранены `PublicCardContent`, изображения, формулы, код, транскрипции
и подсказки. Число показанных карточек отделено от общего размера набора.

SSR, metadata/OpenGraph/canonical, аналитика публичного материала, `noindex, nofollow`
для доступа по ссылке, 404 и `permanentRedirect` в статью курса сохранены.
Общие стили, токены, шапка сайта, API, редактор статьи и профиль автора не менялись.

## Проверки

- 17 тестов: SSR и содержимое, metadata, индексация, 404/503, редирект, пустой набор,
  гостевая сессия, разрешённый доступ, 403/404/503 при проверке доступа и выход из аккаунта.
- ESLint выделенной области, TypeScript публичного сайта и production-сборка Next.js прошли.
  Сборка выполнена в изолированной временной копии, без изменения `.next` локального стенда.
- Браузер: светлая и тёмная темы, 320/390/768/1440/1920 px; текст 200% на 320 px
  в обеих темах, без горизонтального переполнения. Изображения на обеих сторонах загружены,
  KaTeX и подсветка Python отрисованы. Длинные строки не расширяют страницу.
- Клавиатура: видимый фокус, ссылка пропуска шапки, переход к карточкам; цели нажатия
  собственных элементов страницы не меньше 44 px. При reduced motion движение отключено.
- Гость получает страницу входа; вошедший пользователь — ссылку в приложение.
  Владелец временного набора открывает именно его в кабинете, с 54 карточками и режимами.
  Вошедшему постороннему пользователю недоступный переход в набор не предлагается.
- Реальный самостоятельный набор для исходного осмотра:
  `/nabor/проверка-серверной-сборки-5f8964ad` (`course_url: null`).
- Старая ссылка `/nabor/1-11-эмпирическое-распределение-в-python-карточки-243c8fb7`
  ведёт на `/kurs/course-7499b5e0-0b85-4048-a5d6-f0b071e44af8#article-334a71fd-6077-4400-a769-1f2840580782`.
- Прямой HTTP-запрос без исполнения JavaScript содержит заголовок и все 50 карточек
  предпросмотра. Отдельный пустой набор по ссылке возвращает `noindex, nofollow`.

Тестовые материалы созданы в отдельном временном аккаунте: 54 карточки с длинным текстом,
формулами, Python, изображениями, транскрипциями и подсказкой; второй набор — пустой.
Для состояния «по ссылке» изменена только тестовая запись в локальной БД.
Временный аккаунт, оба набора и загруженное изображение удалены после проверки.
Рабочие учебные данные пользователя не изменялись.

## Ограничения существующего API

Чужой самостоятельный набор сейчас нельзя сохранить или скопировать для обучения:
`LibraryService._resolve` и проверка прав обучения требуют связи с опубликованным курсом.
Поэтому прежнее обещание «Начать учиться», которое вело просто на вход, заменено
доступным просмотром карточек. Персональная ссылка в кабинет появляется только после
успешного `GET /api/v1/sets/{id}`. Ошибка этой дополнительной проверки не мешает чтению.
Серверные правила и тарифы не менялись.

Профиль автора без опубликованных курсов может возвращать 404. Страница проверяет
существующий endpoint `/api/v1/authors/{username}` и оставляет имя обычным текстом
при 404, ошибке или тайм-ауте. Переход к существующему `/avtor/Kondr` проверен
на самостоятельном наборе «1.1. Дорожная карта курса».

Публичный endpoint отдаёт максимум 50 карточек и не принимает параметры продолжения.
Страница честно показывает «Показаны первые 50 из 54»; загрузка следующих страниц
не добавлялась через несуществующий контракт.
