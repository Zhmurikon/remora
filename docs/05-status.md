# Состояние Remora на 15 сентября 2026 года

## Итог

E0 собран, основной сценарий E1, этап E2 и основной сценарий E3 завершены. Набор можно создать,
оформить и выучить: планировщик FSRS возвращает карточки по расписанию, работают режимы
«Карточки» и «Заучивание», ответы не теряются при обрыве сети.
Этот отчёт основан на коде и локальных проверках; готовность стейджинга и продакшна не проверена.
Актуальный чек-лист выполненных, незавершённых и отложенных задач ведётся в
[`TODO.md`](../TODO.md).

## Что реализовано

- Монорепозиторий, Next.js, React SPA, FastAPI, слои доступа к данным, единые ошибки и request_id.
- Docker Compose и GitHub Actions. В CI исправлен порядок: миграции выполняются до тестов API.
- Токены оформления и компоненты Button, Input, Card, Badge. Modal и Toast из плана E0 ещё отсутствуют.
- Модели пользователей, настроек, refresh-токенов, OAuth-аккаунтов и согласий; миграция E1.
- API регистрации, подтверждения email, входа, обновления токена, выхода, сброса пароля и текущего пользователя.
- Argon2, локальный словарь простых паролей, JWT access, refresh-cookie с httpOnly, ротация и отзыв семьи при повторном использовании.
- Отправка писем через SMTP и сгенерированная схема TypeScript.
- Одноразовые ссылки подтверждения email и сброса пароля с атомарным погашением.
- Rate limiting через Redis для регистрации, входа и восстановления пароля.
- Защита входа для заблокированных аккаунтов и конкурентная ротация refresh-токенов.
- Схема ORM синхронизирована с миграциями и проверена на чистой базе.
- Страницы входа, регистрации и восстановления пароля в `apps/web`; обработчики одноразовых
  ссылок подтверждения email и смены пароля. Формы адаптивны, работают с API и показывают
  доменные ошибки.
- Дата рождения обязательна в форме регистрации. Соцвходы показаны неактивными заглушками.
- SPA восстанавливает авторизацию через httpOnly refresh-cookie при загрузке, хранит access-токен
  только в памяти и объединяет параллельные попытки refresh в один запрос.
- Маршруты кабинета защищены: гостя возвращает на страницу входа. Добавлены адаптивная
  навигация, выход из аккаунта, пустой кабинет и заглушки разделов наборов, библиотеки и настроек.
- В настройках аккаунта можно изменить имя и локаль, сменить пароль, посмотреть активные
  устройства и завершить отдельную сессию. После смены пароля остальные сессии отзываются.

## E2 завершён

Первый вертикальный срез готов: модели и миграция наборов и карточек, защищённый CRUD,
мягкое удаление и дублирование, атомарное сохранение и изменение порядка карточек. В SPA
добавлены список своих наборов, текстовый редактор с последовательным автосохранением,
индикатор состояния и страница просмотра.

Второй срез готов: вложенные папки с изоляцией пользователей, фильтрация и поиск по библиотеке,
перетаскивание наборов между папками и безопасное удаление папки без удаления наборов. В редакторе
добавлен массовый ввод с настройкой разделителей и предпросмотром; экспорт Quizlet через табуляцию
и переносы строк поддерживается напрямую.

Третий срез готов: карточки поддерживают обычный текст, формулы LaTeX через KaTeX и блоки кода
с выбором языка и подсветкой Shiki. Единый безопасный рендерер используется в предпросмотре редактора
и при просмотре набора; тяжёлые движки загружаются только для формул и кода.

Четвёртый срез готов: к термину и определению можно прикрепить JPEG, PNG, WebP или GIF.
Браузер загружает файл напрямую в приватный S3-бакет по временной ссылке, после чего API
проверяет фактический формат, размер и разрешение. Просмотр работает по короткоживущим
подписанным ссылкам; доступ к метаданным и привязке изображения изолирован по владельцу.

Пятый срез готов: наборы с видимостью «по ссылке» и «публичный» доступны без авторизации
по адресу `/nabor/{slug}-{shortid}`. Next.js рендерит метаданные и первые 50 карточек на сервере,
включая формулы, код и изображения. Приватные, удалённые наборы и наборы неактивных авторов
не раскрываются; страницы «по ссылке» закрыты от индексации. Из кабинета такую страницу можно
открыть в новой вкладке.

Аудио отложено до E4, каталог и SEO — до E6.

## E3 — основной сценарий готов

**Планировщик.** `SchedulerService` — единственное место, где вызывается `py-fsrs` (FSRS-6).
Параметры модели и шаги заучивания скопированы в код и подписаны версией `fsrs6-v1`: обновление
библиотеки не должно молча переписать расписание всем пользователям. Fuzzing выключен намеренно —
иначе интервал на кнопке самооценки расходился бы с тем, что запишет сервер. Провалом считается
только забытая выученная карточка, поэтому список проблемных карточек не забивается новичками.

**Хранение.** Добавлены `card_states`, `reviews`, `study_sessions` и `user_set_progress` с
индексами под выборку очереди. Состояния раздельные по направлениям и создаются лениво — при
первом ответе на карточку, а не при открытии набора.

**Очередь и ответы.** Очередь собирается из просроченных повторений и новых карточек в пределах
дневных лимитов, считаемых по суткам в таймзоне пользователя; новые распределяются равномерно,
две стороны одной карточки разводятся. Ответы принимаются батчами и идемпотентны по
`client_review_id`: уникальный индекс в БД, а не проверка перед вставкой, поэтому параллельный
ретрай не создаёт дубля. Батч разбирается по `reviewed_at`, а не по порядку прихода — иначе
офлайн-очередь дала бы неверные интервалы.

**Сверка клиента с сервером.** В `packages/core` лежит TS-порт FSRS для подписей на кнопках.
Совпадение проверяется по 135 золотым фикстурам, которые генерирует сам серверный планировщик:
`tests/test_fsrs_fixtures.py` ловит расхождение со стороны сервера, `packages/core/src/fsrs.test.ts`
— со стороны клиента.

**Интерфейс.** Общая оболочка тренировки с прогрессом, клавиатурой и индикатором синхронизации;
режим «Карточки» (переворот, свайпы, автопроигрывание, фильтры, опциональная запись в расписание)
и режим «Заучивание» (выбор из вариантов → ввод → свободное воспроизведение по стабильности,
раунды по 8 карточек, разбор ошибок посимвольно). Ответы уходят в localStorage до сетевого
запроса и досылаются после восстановления связи. На странице набора — распределение по состояниям,
прогноз нагрузки на 14 дней и проблемные карточки; в настройках — параметры планировщика.

Следующий этап — E4: «Тест», «Письмо», «Аудирование» и TTS. Общая нормализация ответов пока
заменена мягким сравнением (регистр, пробелы, ё) прямо в режиме «Заучивание».

## Проверки

- `uv run ruff check .` — успешно.
- `uv run mypy app` — успешно, 46 файлов.
- `alembic upgrade head`, `alembic downgrade -1` и `alembic check` — успешно; миграция E3 обратима.
- `uv run pytest` — 65 тестов пройдено, 11 предупреждений httpx и starlette (устаревшие имена).
- `pnpm gen:api`, `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` — успешно.
- Фронтенд-тесты: 168 в `packages/core` (включая 135 кейсов сверки FSRS с сервером) и 8 в
  `apps/app` на очередь неотправленных ответов. Пользовательские сценарии в браузере пока
  не автоматизированы.
- Для API-тестов запущен контейнер PostgreSQL проекта. Почта в тестах подменена; реальная доставка не проверялась.
- Экраны тренировки проверены сборкой и типами, но не ручным прогоном в браузере: он требует
  входа в аккаунт, который агент не выполняет.

Зелёные проверки подтверждают реализованные срезы E2 и E3; технический долг и следующие этапы
перечислены в [`TODO.md`](../TODO.md).
