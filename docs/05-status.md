# Состояние Remora на 15 сентября 2026 года

## Итог

E0 собран, E1 выполнен частично. Приложение пока нельзя использовать для обучения:
публичный сайт и кабинет показывают демонстрационные страницы, наборов и тренировок нет.
Этот отчёт основан на коде и локальных проверках; готовность стейджинга и продакшна не проверена.

## Что реализовано

- Монорепозиторий, Next.js, React SPA, FastAPI, слои доступа к данным, единые ошибки и request_id.
- Docker Compose и GitHub Actions. В CI исправлен порядок: миграции выполняются до тестов API.
- Токены оформления и компоненты Button, Input, Card, Badge. Modal и Toast из плана E0 ещё отсутствуют.
- Модели пользователей, настроек, refresh-токенов, OAuth-аккаунтов и согласий; миграция E1.
- API регистрации, подтверждения email, входа, обновления токена, выхода, сброса пароля и текущего пользователя.
- Argon2, локальный словарь простых паролей, JWT access, refresh-cookie с httpOnly, ротация и отзыв семьи при повторном использовании.
- Отправка писем через SMTP и сгенерированная схема TypeScript.

## Ближайшие задачи E1

### Сначала — защита и надёжность API

1. Сделать токены сброса пароля и подтверждения email одноразовыми. Сейчас JWT принимается повторно до истечения срока; после сброса старой ссылкой можно снова изменить пароль.
2. Добавить ограничение частоты запросов через Redis на вход, регистрацию, восстановление и OAuth.
3. Проверять статус пользователя при входе: сейчас login выдаёт токены также suspended/deleted, хотя refresh и current_user отказывают им в доступе.
4. Обеспечить атомарность ротации refresh-токена: чтение сейчас без блокировки, параллельные запросы могут создать две активные ветки. Добавить конкурентный тест.
5. Согласовать имя cookie: запись использует настройку refresh_cookie_name, чтение жёстко ожидает remora_refresh.
6. Сверить миграцию с ORM: есть различия индексов, ограничений OAuth, типов и серверных значений по умолчанию. Проверить чистую миграцию и отсутствие неожиданного diff Alembic.
7. Обработать конфликт параллельных регистраций единым ответом API; усилить проверки JWT и покрыть некорректные claims тестами.
8. Добавить тесты изоляции двух пользователей, блокировки аккаунта, истечения и повторного использования ссылок, конкурентного refresh, rate limiting и OAuth.

### Затем — закончить пользовательский сценарий

1. OAuth VK ID, Яндекс ID, Telegram и связывание аккаунтов. Таблица уже есть, обработчиков нет.
2. Страницы входа, регистрации и восстановления в apps/web; обработчики ссылок из писем. Сейчас письма ведут в SPA, где этих маршрутов нет.
3. Защищённые маршруты SPA, навигация, хранение состояния авторизации и single-flight refresh.
4. Пустой кабинет и настройки: профиль, пароль, аккаунты, список устройств и отзыв сессий.
5. Довести возрастной гейт до пользовательского сценария: birth_date и вычисляемое свойство есть, обязательного сбора даты и процедуры согласия нет.
6. Проверить SMTP с реальным отправителем, приложения провайдеров и домены; пройти E1 end-to-end на стейджинге.

## Проверки

- `uv run ruff check .` — успешно.
- `uv run mypy app` — успешно, 27 файлов.
- `alembic upgrade head` на локальной remora_test — успешно; чистая база отдельно не проверялась.
- `uv run pytest` — 17 тестов пройдено, 5 предупреждений httpx о передаче cookies в отдельный запрос.
- `pnpm gen:api`, `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` — успешно.
- Тесты фронтенда сейчас покрывают утилиты packages/core, а не пользовательские сценарии.
- Для API-тестов запущен контейнер PostgreSQL проекта. Почта в тестах подменена; реальная доставка не проверялась.

Зелёные проверки подтверждают существующее покрытие, но не закрывают перечисленные задачи E1.
