# Практика Python

## Решение

В кабинете появляется раздел **«Практика»**. На первом этапе внутри него доступен один
тренажёр — **«Python»**. Такая иерархия не привязывает навигацию к одному языку и позволяет
позже добавить SQL, регулярные выражения или другие практические модули без переименования
раздела.

Основные маршруты:

- `/practice` — каталог тренажёров и прогресс;
- `/practice/python` — список задач Python;
- `/practice/python/:taskSlug` — условие, редактор и результат проверки.

Практика относится к авторизованной интерактивной части продукта и реализуется в
`apps/app`. Публичные страницы задач и SEO в первый выпуск не входят.

## Зачем это продукту

Карточки помогают запоминать синтаксис и понятия, но не проверяют умение написать программу.
Практика закрывает следующий шаг: прочитать небольшое условие, запустить код, увидеть ошибку
и довести решение до проходящих проверок. Это самостоятельный сценарий, а не новый режим
FSRS: выполнение задач не меняет расписание карточек.

## Границы первой версии

В первую версию входят:

- встроенный каталог из 15–20 коротких задач начального уровня;
- темы «Вывод и переменные», «Условия», «Циклы», «Строки», «Списки» и «Функции»;
- редактор с подсветкой Python, запуском с клавиатуры и восстановлением черновика;
- `stdout`, `stderr`, синтаксические ошибки и ограниченный текстовый ввод;
- отдельные действия «Запустить» и «Проверить решение»;
- выполнение CPython через Pyodide в браузерном Web Worker;
- ограничение времени, объёма вывода и аварийная остановка worker;
- локальный прогресс: не начато, в работе, решено, число попыток и последний черновик;
- светлая и тёмная темы, ширина от 320 px, управление с клавиатуры.

В первую версию не входят:

- выполнение пользовательского кода на сервере;
- рейтинги, соревнования, сертификаты и экзаменационная проверка;
- создание и публикация задач пользователями;
- произвольная установка пакетов и доступ к файлам устройства;
- мобильные приложения и боты;
- начисление XP и изменение FSRS-прогресса;
- гарантированно скрытые тесты: код проверок, доставленный в браузер, нельзя считать секретным.

Обучение и число запусков не ограничиваются тарифом.

## Техническая схема

```text
Страница задачи
  ├── условие и примеры
  ├── редактор CodeMirror
  └── команды run / check / stop
                │
                ▼
        Web Worker с Pyodide
          ├── отдельное пространство выполнения
          ├── перехват stdout / stderr / input
          ├── запуск проверочных сценариев
          └── структурированный результат
                │
                ▼
      интерфейс результата и localStorage
```

Pyodide загружается лениво при первом открытии задачи. Версия фиксируется, необходимые
артефакты отдаются с инфраструктуры Remora, чтобы работоспособность не зависела от внешнего
CDN. Тяжёлые научные пакеты не загружаются. Повторные открытия используют браузерный кэш.

Worker получает только исходный код, входные данные и описание запуска. Access-токен,
профиль пользователя и другие данные приложения ему не передаются. По таймауту worker
завершается целиком и создаётся заново. Результат ограничивается по длине, чтобы бесконечный
`print` не исчерпал память вкладки.

Браузерный worker защищает интерфейс от зависания, но не является границей для запуска
враждебного кода. В первом выпуске исполняется только текст, который набрал или вставил сам
пользователь; импорт и запуск чужих решений запрещены. Если появится пользовательский обмен
кодом или экзаменационный режим, исполнитель нужно изолировать на отдельном origin либо
перенести в серверный sandbox.

## Контракт задачи

Задачи первого выпуска хранятся в версионированных TypeScript/JSON-данных внутри
`apps/app`. Одна задача содержит:

- стабильные `id`, `slug` и `version`;
- название, тему, сложность и короткое условие;
- стартовый код;
- примеры входа и выхода;
- режим проверки: вывод программы или вызов функции;
- набор проверочных сценариев и понятные сообщения об ошибках;
- необязательную подсказку и эталонное объяснение после решения.

Проверяющий возвращает машиночитаемый результат:

```ts
type PythonRunResult = {
  status: 'passed' | 'failed' | 'runtime_error' | 'timeout' | 'stopped';
  stdout: string;
  stderr: string;
  durationMs: number;
  checks?: Array<{
    name: string;
    passed: boolean;
    message?: string;
  }>;
};
```

Тексты исключений и результаты проверок отображаются как обычный текст, без исполнения HTML.

## Этапы разработки

### P0. Контракт и каркас

- Зафиксировать продуктовые границы, маршруты и формат задания.
- Добавить вкладку «Практика», маршруты и состояния пустого каталога/ошибки.
- Собрать каталог на статических данных и одну демонстрационную задачу без выполнения кода.
- Покрыть навигацию и маршрутизацию тестами.

**Готово, когда:** раздел открывается из основной навигации на мобильном и десктопе, а
прямые ссылки на каталог и задачу работают после перезагрузки.

### P1. Исполнитель Python

- Подключить зафиксированную версию Pyodide и ленивую загрузку.
- Реализовать отдельный module worker и типизированный протокол сообщений.
- Перехватывать вывод и исключения, поддержать ограниченный `input()`.
- Добавить запуск, остановку, таймаут и пересоздание worker после сбоя.
- Ограничить объём вывода и не разрешать произвольную установку пакетов.

**Готово, когда:** обычная программа, ошибка, бесконечный цикл, большой вывод и повторный
запуск после остановки обрабатываются предсказуемо и не блокируют интерфейс.

### P2. Редактор и проверка решений

- Подключить CodeMirror с Python-подсветкой, нумерацией строк и корректным вводом Tab.
- Разделить «Запустить» и «Проверить решение».
- Реализовать проверки вывода и функций в чистом пространстве выполнения.
- Показать прошедшие проверки, первую полезную ошибку и итог задачи.
- Добавить горячую клавишу запуска, видимый фокус и доступные подписи элементов.

**Готово, когда:** демонстрационная задача решается полностью с клавиатуры, а пользователь
понимает разницу между ошибкой Python и неверным ответом.

### P3. Локальный прогресс и устойчивость

- Сохранять черновик, статус и число попыток по `taskId + version`.
- Восстанавливать работу после перезагрузки и повреждённых локальных данных.
- Добавить фильтры по теме и статусу, общий прогресс и переход к следующей задаче.
- Проверить поведение без сети после первичной загрузки рантайма.
- Провести визуальную проверку на 320, 768 и 1440 px в обеих темах.

**Готово, когда:** закрытие вкладки не теряет решение, обновление задания не смешивает
несовместимый прогресс, а каталог показывает фактическое состояние задач.

### P4. Учебное наполнение

- Подготовить 15–20 задач по шести начальным темам.
- Для каждой задачи добавить примеры, пограничные проверки, подсказку и разбор.
- Проверить формулировки на однозначность и решения на обычном CPython той же версии.
- Добавить регрессионные тесты каталога и всех проверяющих сценариев.

**Готово, когда:** каждую задачу проходит эталонное решение и не проходит набор типичных
ошибочных решений, а порядок задач образует понятную учебную последовательность.

### P5. Синхронизация после проверки спроса

- Добавить серверную модель прогресса без хранения каждого запуска и полного вывода.
- Синхронизировать лучший статус и последний черновик с защитой от конфликтов.
- Сохранить локальную очередь при потере сети и идемпотентную отправку.
- Решить по данным, связывать ли практику с курсами, заданиями преподавателя и XP.

Этот этап не нужен для первого пользовательского теста. Серверная проверка добавляется
отдельно только для сценариев, где результату нельзя доверять на клиенте.

## Проверки перед выпуском

- unit-тесты протокола worker, ограничений и проверки задач;
- тесты маршрутов, каталога, восстановления прогресса и клавиатуры;
- `pnpm lint`, `pnpm typecheck`, `pnpm test`, production-сборка кабинета;
- ручная проверка Chrome, Firefox и Safari;
- бесконечный цикл, рекурсия до ошибки, большой вывод, пустой ввод и повторная остановка;
- отсутствие запросов к API при запуске и проверке кода;
- отсутствие токенов и пользовательских данных в сообщениях worker.

## Метрики решения о продолжении

До P5 достаточно анонимных продуктовых событий без текста решений:

- открытие раздела и задачи;
- первый запуск;
- успешное решение;
- число попыток и время до решения;
- остановка по таймауту;
- возвращение в практику в течение семи дней.

Текст программы, stdin и вывод в аналитику не отправляются.
