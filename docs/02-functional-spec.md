# Remora — структура функционала и архитектура

Уточнение E6: решения о курсах, плоских тегах, публикации и сохранениях зафиксированы
в [брифе E6](06-courses-brief.md) и заменяют прежние положения о публичных наборах и категориях.

## 1. Карта функциональных доменов

```
Remora
├── 1. Идентичность и аккаунт
```

## 2. Архитектура

### 2.1 Схема

```
                      ┌───────────────────────────┐
   поисковые боты ──> │  remora.ru                │
   и анонимы          │  Next.js SSR (public web) │──┐
                      └───────────────────────────┘  │
                                                     │  HTTP (внутр. сеть)
                      ┌───────────────────────────┐  │
   залогиненные   ──> │  app.remora.ru            │  │
   пользователи       │  React SPA (Vite)         │──┤
                      └───────────────────────────┘  │
                                                     ▼
                                      ┌──────────────────────────┐
                                      │  api.remora.ru           │
                                      │  FastAPI (Python 3.12)   │
                                      └──────────────────────────┘
                                        │        │         │
                          ┌─────────────┘        │         └──────────────┐
                          ▼                      ▼                        ▼
                  ┌──────────────┐      ┌────────────────┐       ┌────────────────┐
                  │ PostgreSQL16 │      │ Redis          │       │ S3 (Selectel)  │
                  │ основные     │      │ кэш, лимиты,   │       │ картинки,      │
                  │ данные       │      │ очередь ARQ    │       │ аудио TTS      │
                  └──────────────┘      └────────────────┘       └────────────────┘
                          │                      │
                          ▼                      ▼
                  ┌──────────────┐      ┌────────────────┐
                  │ Meilisearch  │      │ ARQ workers    │
                  │ поиск набор. │      │ TTS, импорт,   │
                  └──────────────┘      │ отчёты, письма │
                                        └────────────────┘
```

### 2.2 Граница между двумя фронтендами (важно, иначе они расползутся)

**Next.js `remora.ru` — публичный сайт.** Отвечает за всё, что должен видеть поисковый робот и незалогиненный человек:

- Лендинг, страницы тарифов, справка, юридические документы, блог.
- Каталог наборов, страницы категорий и предметов.
- Страница публичного набора: список карточек в HTML, метаданные, микроразметка.
- Профиль автора (публичный).
- Форма входа и регистрации (после успеха — редирект в SPA).

**Vite React SPA `app.remora.ru` — приложение.** Всё, что за логином и не индексируется:

- Кабинет, библиотека, папки.
- Редактор наборов и карточек.
- Все режимы обучения (высокая интерактивность, требуется локальное состояние и оптимистичные обновления).
- Классы, задания, отчёты.
- Настройки, подписка.

**Правило:** если страница должна попасть в Яндекс — это Next.js. Если это интерактивная работа авторизованного пользователя — это SPA. Промежуточных случаев не создаём.

**Общий код в монорепо (pnpm workspaces):**

```
remora/
├── apps/
│   ├── api/          FastAPI
│   ├── web/          Next.js (публичный)
│   └── app/          Vite React SPA
├── packages/
│   ├── ui/           дизайн-система, общие компоненты (React)
│   ├── api-client/   TypeScript-клиент, генерируется из OpenAPI
│   ├── core/         общая логика: FSRS-предпросмотр, нормализация ответов,
│   │                 форматирование, типы доменных сущностей
│   └── config/       eslint, tsconfig, tailwind preset
└── docs/
```

`packages/core` дублирует часть логики бэкенда на TS сознательно: движок обучения должен отвечать мгновенно, без сетевого раунд-трипа на каждую карточку. Сервер остаётся источником истины и пересчитывает всё при синхронизации.

### 2.3 Стек по слоям

**Бэкенд**

- FastAPI, Pydantic v2, SQLAlchemy 2.0 (async), Alembic.
- PostgreSQL 16: основные данные, полнотекстовый поиск как резерв.
- Redis: кэш, rate limiting, брокер для ARQ.
- ARQ (или Celery): TTS-генерация, импорт больших файлов, сборка отчётов, рассылки, пересчёт статистики.
- Meilisearch: поиск по наборам с русской морфологией и опечатками.
- `fsrs` (py-fsrs, MIT) — алгоритм повторений.
- Хранилище: S3-совместимое (Selectel Object Storage), отдача через CDN.
- Аутентификация: собственная. Access JWT 15 мин (в памяти SPA), refresh-токен в httpOnly Secure cookie на 30 дней, ротация с детекцией переиспользования.

**Фронтенд (оба приложения)**

- React 19, TypeScript strict.
- TanStack Query — серверное состояние, Zustand — локальное состояние сессии обучения.
- Tailwind CSS + собственная дизайн-система в `packages/ui` (на базе Radix primitives).
- KaTeX для формул, Shiki для подсветки кода.
- Формы: react-hook-form + zod (схемы генерируются из OpenAPI где возможно).

**Инфраструктура**

- Docker Compose для локальной разработки и продакшна на одном сервере.
- Nginx / Caddy как реверс-прокси и TLS.
- GitHub Actions или GitLab CI: линт, типы, тесты, сборка образов, деплой.
- Sentry (self-hosted или облако), Prometheus + Grafana, структурные логи в JSON.

## 3. Модель данных

Подробно — таблицы и ключевые поля. Всё с `id UUID`, `created_at`, `updated_at`.

### 3.1 Идентичность

**users** — `email` (уникальный, nullable для соцвхода), `password_hash` (argon2id, nullable), `username` (уникальный, для публичного URL), `display_name`, `avatar_url`, `role` (`user` | `teacher` | `moderator` | `admin`), `email_verified_at`, `birth_date` (для возрастного гейта), `locale`, `timezone`, `status` (`active` | `suspended` | `deleted`), `deleted_at`.

**oauth_accounts** — `user_id`, `provider` (`vk` | `yandex` | `telegram`), `provider_user_id`, `raw_profile` (jsonb). Уникальность по (provider, provider_user_id).

**refresh_tokens** — `user_id`, `token_hash`, `family_id`, `expires_at`, `revoked_at`, `user_agent`, `ip`. Ротация: при использовании старого токена вся семья отзывается.

**user_settings** — `user_id`, `daily_goal_cards`, `fsrs_desired_retention` (по умолчанию 0.90), `fsrs_max_interval_days`, `new_cards_per_day`, `reviews_per_day`, `tts_voice_preference`, `notification_channels` (jsonb), `theme`.

**consents** — `user_id`, `kind` (`pdn` | `offer` | `marketing` | `guardian`), `version`, `accepted_at`, `ip`. Нужно для 152-ФЗ.

### 3.2 Контент

**folders** — `owner_id`, `parent_id` (самоссылка), `title`, `color`, `position`.

**study_sets** — `owner_id`, `folder_id`, `title`, `description`, `subject_id`, `lang_term` (ISO-код языка стороны «термин»), `lang_definition`, `visibility` (`private` | `unlisted` | `public`), `slug` (для SEO-URL), `cards_count` (денормализовано), `copied_from_id`, `is_template`, `moderation_status` (`ok` | `pending` | `blocked`), `published_at`, `stats` (jsonb: просмотры, копирования, лайки).

**cards** — `set_id`, `position`, `term` (текст с ограниченным Markdown), `definition`, `term_transcription`, `definition_transcription`, `hint`, `term_image_id`, `definition_image_id`, `term_audio_id`, `definition_audio_id`, `content_type` (`text` | `latex` | `code`), `code_language`, `alt_answers` (массив: допустимые синонимы для режима «Письмо»), `is_starred_by` — нет, вынесено отдельно.

**card_stars** — `user_id`, `card_id`. «Избранные»/«сложные» карточки пользователя, включая чужие наборы.

Дополнение карточек: `wrong_term_answers` и `wrong_definition_answers` — необязательные
массивы неверных ответов, отдельно для обратного и прямого направления. Технический предел —
30 вариантов на сторону, до 10 000 символов каждый. Пустые варианты, повторы и совпадения
с правильным ответом или `alt_answers` запрещены (регистр, пробелы и ё/е нормализуются).
В вопросах с выбором сначала берутся до трёх случайных авторских вариантов, недостающие —
из других карточек; все четыре ответа перемешиваются. При нехватке вариантов используется
ввод ответа. Выбор готовой кнопки проверяется без допуска опечаток. Письмо, просмотр карточек,
верно/неверно и сопоставление не меняются. Полный ZIP-экспорт сохраняет оба массива;
двухколоночные TXT/CSV/Anki и PDF сохраняют прежний формат. ИИ-генерация отложена.

**media_assets** — `owner_id`, `kind` (`image` | `audio`), `s3_key`, `mime`, `size_bytes`, `width`, `height`, `duration_ms`, `checksum` (sha256, для дедупликации), `source` (`upload` | `tts`), `moderation_status`.

**tts_cache** — `text_hash` (sha256 от текста+голоса+языка), `voice`, `lang`, `media_asset_id`, `char_count`, `hits`. Отдельно от media_assets, чтобы одинаковые слова у миллиона пользователей стоили одну генерацию.

**subjects** — иерархический справочник предметов: `parent_id`, `title`, `slug`, `level` (`school` | `university` | `lang` | `pro`). Основа для SEO-структуры каталога.

**set_tags** / **tags** — свободные теги наборов.

### 3.3 Обучение

**card_states** — состояние FSRS для пары (пользователь, карточка). Самая горячая таблица.

- `user_id`, `card_id`, `set_id` (денорм. для быстрых выборок)
- `direction` (`term_to_def` | `def_to_term`) — состояния для двух направлений раздельные
- `state` (`new` | `learning` | `review` | `relearning`)
- `stability` (float), `difficulty` (float)
- `due_at` (timestamptz), `last_reviewed_at`
- `reps`, `lapses`, `elapsed_days`, `scheduled_days`
- `suspended_at` — карточка отложена пользователем
- Индексы: `(user_id, due_at)` частичный по неотложенным, `(user_id, set_id, state)`

**reviews** — иммутабельный журнал каждого ответа. Основа аналитики и будущей переоптимизации параметров FSRS.

- `user_id`, `card_id`, `direction`, `session_id`, `mode` (`flashcards` | `learn` | `test` | `write` | `listen`)
- `rating` (1 again / 2 hard / 3 good / 4 easy), `answer_correct` (bool)
- `duration_ms`, `reviewed_at`
- `state_before` (jsonb), `state_after` (jsonb), `scheduler_version`
- Партиционирование по месяцам при росте.

**study_sessions** — `user_id`, `set_id` или `assignment_id`, `mode`, `started_at`, `ended_at`, `cards_seen`, `cards_correct`, `config` (jsonb: настройки сессии), `status`.

**test_attempts** — `user_id`, `set_id`, `config` (число вопросов, типы, направление), `questions` (jsonb — зафиксированный список), `answers` (jsonb), `score`, `finished_at`.

**user_set_progress** — денормализованная сводка: `user_id`, `set_id`, `mastered_count`, `learning_count`, `not_started_count`, `last_studied_at`, `mastery_percent`. Пересчитывается фоново и при завершении сессии.

### 3.4 Учебный контур

**classes** — `owner_id`, `title`, `description`, `join_code` (короткий, ротируемый), `school_id` (nullable), `archived_at`, `settings` (jsonb: нужно ли одобрение вступления).

**class_members** — `class_id`, `user_id`, `role` (`teacher` | `assistant` | `student`), `joined_at`, `status`.

**class_sets** — какие наборы расшарены в класс: `class_id`, `set_id`, `added_by`.

**assignments** — `class_id`, `set_id`, `title`, `mode_required` (какой режим засчитывается), `goal_type` (`mastery_percent` | `cards_count` | `test_score`), `goal_value`, `open_at`, `due_at`, `created_by`.

**assignment_progress** — `assignment_id`, `user_id`, `progress_value`, `completed_at`, `last_activity_at`, `status` (`not_started` | `in_progress` | `done` | `late`).

### 3.5 Удержание

**streaks** — `user_id`, `current_days`, `longest_days`, `last_active_date`, `freezes_left`.
**daily_activity** — `user_id`, `date`, `cards_reviewed`, `minutes`, `goal_met`, `xp_earned`. Одна строка на пользователя в день, основа графика активности.
**achievements** / **user_achievements** — справочник + выданные.
**notifications_queue** — `user_id`, `channel` (`email` | `telegram` | `webpush`), `kind`, `payload`, `send_after`, `sent_at`, `status`.

### 3.6 Монетизация

**plans** — `code` (`free` | `plus` | `teach` | `school`), `title`, `price_month`, `price_year`, `features` (jsonb), `active`.
**subscriptions** — `user_id`, `plan_code`, `status` (`trialing` | `active` | `past_due` | `canceled` | `expired`), `current_period_start/end`, `cancel_at_period_end`, `payment_method_id` (токен ЮKassa для автоплатежа), `provider`, `provider_subscription_id`.
**payments** — `user_id`, `subscription_id`, `provider_payment_id`, `amount`, `currency`, `status`, `receipt_url`, `raw` (jsonb), `paid_at`.
**payment_events** — сырой лог вебхуков с `idempotency_key`. Обработка строго идемпотентная.
**entitlements** — персональные переопределения прав: `user_id`, `feature`, `limit_value`, `valid_until`, `reason`. Отдельная таблица, чтобы разовые бонусы и промо не ломали логику подписки.
**usage_counters** — `user_id`, `metric` (`tts.chars_month`, `import.per_day`, `copy.per_day`, `export.account_per_day`), `period_key` (`2026-09` или `2026-09-08`), `value`. PK `(user_id, metric, period_key)`, инкремент через `INSERT ... ON CONFLICT DO UPDATE`. Сброс не требуется: новый период — новый ключ, старые строки чистятся фоновой задачей.

### 3.7 Модерация и служебное

**reports** — жалобы на контент: `reporter_id`, `target_type`, `target_id`, `reason`, `comment`, `status`, `resolved_by`.
**moderation_actions** — лог действий модератора.
**audit_log** — значимые действия (смена роли, удаление набора, возврат платежа).
**feature_flags** — управление раскаткой.

## 4. Функциональные требования по модулям

### 4.1 Идентичность

- Регистрация email+пароль с подтверждением по ссылке. Пароль — argon2id, минимум 8 символов, проверка по списку утечек (k-anonymity через HIBP или локальный словарь).
- Вход через VK ID, Яндекс ID, Telegram Login Widget. При совпадении email — связывание с существующим аккаунтом, но только после подтверждения владения почтой.
- Восстановление пароля по одноразовой ссылке (срок 30 минут, одноразовость гарантируется).
- Возрастной гейт: при регистрации спрашиваем дату рождения. Младше 14 лет — регистрация с указанием email представителя и получением согласия (E10).
- Управление сессиями: список активных устройств, выход отовсюду.
- Удаление аккаунта: мягкое (30 дней) → жёсткое. Публичные наборы при удалении: пользователь выбирает — удалить или передать в «архив сообщества» анонимно.
- Rate limiting на всё, что связано с паролями и кодами.

### 4.2 Контент

**Наборы**

- Создание, редактирование, удаление, дублирование.
- Массовое создание карточек из текста: вставка списка с настраиваемыми разделителями (таб/запятая/произвольный между сторонами, перенос строки/точка с запятой между карточками) и живым предпросмотром распознанного результата. Это критично: так люди переносят материал быстрее всего.
- Реорганизация карточек drag-and-drop, автосохранение черновика, отмена действия.
- Видимость: приватный / по ссылке / публичный. Публикация проходит через проверку на минимальное качество (≥ 4 карточек, есть название, нет пустых сторон).
- Копирование чужого публичного набора в свою библиотеку с сохранением ссылки на первоисточник.
- Комбинирование: создание набора из карточек нескольких других наборов и из «сложных» карточек.

**Карточки**

- Две стороны: термин и определение. У каждой — текст, необязательные транскрипция, изображение, аудио.
- Ограниченный Markdown: жирный, курсив, подчёркивание, переносы, списки. Санитизация на сервере, whitelist-подход.
- Формулы: инлайн `$...$` и блочные `$$...$$`, рендер KaTeX. Валидация на этапе сохранения, чтобы битая формула не ломала тренировку.
- Код: fenced-блоки с указанием языка, подсветка Shiki, моноширинный шрифт, сохранение отступов.
- Изображения: загрузка до 5 МБ, конвертация в WebP + AVIF, три размера (thumb 200px, card 800px, full 1600px), EXIF-очистка, проверка mime по содержимому, а не по расширению.
- Аудио: либо загрузка пользователя, либо генерация TTS по кнопке. Кэш обязателен.
- Альтернативные ответы: список синонимов, засчитываемых как верные в режимах «Письмо» и «Тест».

**Организация**

- Папки с вложенностью (ограничить 3 уровнями), перетаскивание наборов.
- Поиск по своей библиотеке: по названию, содержимому карточек, тегам.
- Недавние, избранные, «требуют повторения сегодня» — системные подборки на главной кабинета.

**Импорт**

- Вставка текста (основной путь для миграции с Quizlet: там есть «Экспорт» в текст).
- CSV/TSV с маппингом колонок в UI.
- Anki `.apkg`: разбор SQLite внутри архива, извлечение полей заметок, медиа-файлов, поддержка базовых типов заметок. Сложные шаблоны — приводим к двум сторонам с предупреждением пользователю.
- Anki `.txt` экспорт.
- Импорт больших файлов — фоновая задача с прогрессом и отчётом об ошибках построчно.

**Экспорт**

- Набор: TXT (настраиваемые разделители), CSV, Anki-совместимый TXT, PDF на печать (сетка карточек для вырезания, 2 варианта раскладки).
- Весь аккаунт: ZIP с JSON всех наборов, историей обучения и медиа. Обязательство «твои данные — твои» должно быть реальным, это часть позиционирования.

### 4.3 Движок обучения

**Общая механика**

- Источник истины по расписанию — сервер. Клиент получает пачку карточек на сессию (например, 60 штук) вместе с предвычисленными вариантами интервалов, отвечает локально, отправляет ответы батчами каждые N ответов и при завершении. Потеря соединения не должна терять прогресс: очередь ответов в localStorage с повторной отправкой.
- Идемпотентность отправки ответов по `client_review_id` (UUID генерируется на клиенте).
- Направление изучения: термин→определение, определение→термин, оба. Состояния FSRS раздельные по направлению.

**Режим «Карточки» (Flashcards)**

- Переворот карточки по клику/пробелу, навигация стрелками, свайп на тач-устройствах.
- Автопроигрывание с настраиваемой паузой, автоозвучка.
- Метка «знаю / не знаю» — опционально пишет в FSRS (настройка), по умолчанию — легковесный просмотр без влияния на расписание.
- Перемешивание, фильтр «только сложные», «только не начатые».

**Режим «Заучивание» (Learn) — ядро продукта**

- Планировщик FSRS: очередь на сегодня = просроченные повторения + новые карточки в пределах дневного лимита.
- Прогрессия типов вопросов внутри карточки: узнавание (выбор из 4) → ввод ответа → свободное воспроизведение. Тип подбирается по стабильности карточки.
- Оценка: для вопросов с выбором — верно/неверно маппится в FSRS rating (again/good). Для свободного ввода — доступны 4 кнопки самооценки после проверки.
- Раунды по 7–10 карточек с промежуточным экраном прогресса, чтобы дать чувство завершённости.
- Умный разбор ошибки: показываем, что было введено, что ожидалось, подсвечиваем различие по символам.
- Режим «Подготовка к экзамену»: пользователь указывает дату, система строит план — сколько карточек в день нужно, чтобы к дате процент удержания был ≥ целевого; при отставании предупреждает. Это фича, которой у Quizlet нет и которая напрямую бьёт в мотивацию «у меня контрольная в четверг».

**Режим «Тест»**

- Настройка: количество вопросов, типы (выбор из 4, верно/неверно, ввод, сопоставление), направление, источник (весь набор / только сложные / только невыученные).
- Прохождение без подсказок, проверка в конце, страница результатов с разбором.
- Пересдача с фокусом на ошибках.
- Печатная версия теста (PDF) с отдельным листом ответов — для преподавателей это неожиданно весомый аргумент.

**Режим «Письмо»**

- Ввод ответа текстом. Нечёткое сравнение: игнор регистра и лишних пробелов, нормализация ё/е, опциональный игнор диакритики и артиклей, расстояние Левенштейна с порогом, зависящим от длины, учёт `alt_answers`.
- При «почти верно» — отдельный статус «опечатка», не считается ошибкой, но требует повторного ввода.
- Настройка строгости: строго / умеренно / мягко.

**Режим «Аудирование»**

- Воспроизводится TTS-озвучка стороны, ответ вводится или выбирается.
- Настройка скорости воспроизведения, повтор.
- Для языковых наборов — режим «диктант»: слышим, пишем полностью.

**Статистика обучения**

- На странице набора доступен сброс своего прогресса с подтверждением: удаляются текущие
  состояния FSRS обоих направлений, но не карточки, журнал ответов и история занятий.
  Расписание общее для режимов; активные сессии закрываются, старые тесты больше не пишут
  в расписание. В `user_set_progress.reset_at` хранится граница сброса: запоздавшие ответы
  до неё отклоняются, старые сессии не могут восстановить прогресс. Сброс и запись ответов
  сериализуются транзакционной блокировкой пользователя. Исторические ответы до сброса
  не расходуют текущие дневные лимиты обучения. Перед сбросом клиент синхронизирует очередь;
  при ошибке сброс не выполняется. Параметры и версия планировщика не меняются.

- По набору: процент освоения, распределение карточек по состояниям, список проблемных карточек, прогноз «когда будет выучен полностью».
- По пользователю: активность по дням (heatmap), суммарное время, число повторений, кривая удержания, список карточек к повторению на ближайшие 7 дней.
- Тяжёлые агрегаты считаются фоновой задачей раз в сутки + инкрементально при завершении сессии.

### 4.4 Публичный слой и SEO

- Каталог: `/nabory`, разделы по предметам `/predmet/{slug}`, по языкам `/yazyki/{slug}`, по уровням.
- Страница набора: `/nabor/{slug}-{shortid}` — SSR со всеми карточками в HTML, но с ограничением (первые 50 карточек в разметке, остальные подгружаются). Кнопки «Учить», «Скопировать», «Скачать».
- Meilisearch по названию, описанию, содержимому карточек, тегам. Русская морфология, опечатки, фасеты по предмету, языку, размеру набора.
- SEO-обвязка: канонические URL, `sitemap.xml` с сегментацией и автогенерацией, `robots.txt`, Open Graph + Twitter Card, JSON-LD (`Quiz`, `LearningResource`, `BreadcrumbList`), hreflang при появлении локалей.
- Производительность как ранжирующий фактор: LCP < 2.0 c на 4G, серверный кэш HTML публичных страниц в Redis, ISR-подобная ревалидация, изображения в AVIF/WebP с явными размерами.
- Защита от парсинга: rate limiting по IP, но без блокировки поисковых ботов (проверка по обратному DNS).
- Публичный профиль автора со списком наборов — дополнительная индексируемая поверхность.

### 4.5 Удержание

- Стрик: засчитывается день, если выполнена дневная цель (по умолчанию 20 карточек). Заморозки: 2 в месяц, чтобы пропуск не обнулял мотивацию полностью.
- Дневная цель настраивается, показывается кольцом прогресса.
- XP за повторения с понижающим коэффициентом внутри дня (защита от накрутки), уровни.
- Достижения: за серии, за объём, за первый созданный набор, за импорт, за помощь классу.
- Напоминания: email (дайджест «сегодня к повторению N карточек»), Telegram-бот (для тех, кто вошёл через Telegram — самый высокий отклик), web-push. Время отправки — по таймзоне пользователя, частота настраивается, отписка в один клик.
- Лидерборд — только внутри класса или среди друзей. Глобальный лидерборд для учебного продукта вреден.

### 4.6 Учебный контур

**Преподаватель**

- Создаёт класс, получает код и ссылку-приглашение. Ученик вступает по коду без email-приглашений (важно: у школьников часто нет рабочей почты).
- Расшаривает наборы в класс, создаёт задания: набор + цель + дедлайн.
- Дашборд класса: таблица «ученики × задания» со статусами, средний прогресс, кто не приступал, кто отстаёт.
- Отчёт по ученику: динамика, слабые карточки, время занятий.
- Отчёт по карточке: какие карточки чаще всего ошибочны у всего класса — прямой сигнал для урока. Это сильная фича, ради неё преподаватели остаются.
- Выгрузка отчётов в XLSX.
- Архивирование класса и копирование его структуры на новый учебный год.

**Ученик**

- Видит список заданий с дедлайнами и прогрессом, входит в тренировку одной кнопкой.
- Получает напоминание за 24 часа до дедлайна.
- Прогресс по заданию считается от реального состояния FSRS, а не от «прокликал N раз».

**Границы MVP-версии контура:** без интеграций с электронными журналами, без родительских кабинетов, без оценок в баллах. Всё это — после подтверждения спроса.

### 4.7 Монетизация

- Тарифная страница на публичном сайте, оформление внутри SPA.
- ЮKassa: создание платежа, редирект/виджет, вебхук `payment.succeeded`, сохранение способа оплаты для рекуррентных списаний, автоплатёж по расписанию за N дней до конца периода.
- 54-ФЗ: передача состава чека при создании платежа, ссылка на чек в истории.
- Обработка неуспешных списаний: 3 попытки с интервалами, статус `past_due`, мягкая деградация (доступ к обучению сохраняется, отключаются платные удобства), уведомления.
- Отмена подписки в один клик без «позвоните нам», возвраты по регламенту.
- Проверка прав в API — через единый сервис `Entitlements` (`feature` / `limit` / `check` / `consume`), а не разбросанными `if plan == ...`.
- Значения лимитов хранятся в одном YAML-конфиге, из которого сидируется `plans.features`. Персональные переопределения (промо, ручная выдача) — в `entitlements`.
- Два типа ограничений: квоты состояния (наборы, карточки, изображения, классы — считаются по базе с кэшем) и счётчики за период (`usage_counters`: символы TTS в месяц, импорты и копирования в сутки).
- При превышении — ошибка `LIMIT_EXCEEDED` с машиночитаемыми `limit_key`, `limit`, `current`, `resets_at`, `upgrade_to`. Клиент выбирает экран по `limit_key`, не парся текст.
- Массовые операции (импорт, батчевое добавление карточек) проверяют лимит до начала и явно сообщают, сколько записей не добавлено. Молчаливая обрезка запрещена.
- Сессия обучения не прерывается лимитом никогда: при исчерпании квоты TTS режим продолжает работать без озвучки.
- Grandfathering: контент, созданный до ужесточения лимита, не блокируется.

Полная таблица лимитов, механика реализации и поведение при превышении — в [04-limits.md](04-limits.md).

### 4.8 Платформа

- **Медиа:** загрузка через presigned URL напрямую в S3, затем фоновая обработка (валидация, конвертация, размеры, дедупликация по checksum). Отдача через CDN с длинным кэшем и версионированными ключами.
- **TTS:** Яндекс SpeechKit. Синтез только по явному запросу или при первом воспроизведении. Ключ кэша — sha256(текст + язык + голос + скорость). Учёт символов в `usage_counters`. Пакетная генерация для набора — фоновая задача.
- **Модерация:** очередь публичных наборов, автоматические фильтры (стоп-слова, доля не-текста), жалобы пользователей, действия модератора с логированием. Блокировка убирает набор из индекса, но не удаляет данные автора.
- **Админ-панель:** пользователи, наборы, жалобы, подписки и платежи, фиче-флаги, ручная выдача прав, просмотр фоновых задач. Отдельный домен, вход только с 2FA, доступ по IP-списку.
- **Наблюдаемость:** Sentry для ошибок, метрики Prometheus (латентность API, длина очередей, доля 5xx, время генерации TTS), алерты в Telegram, структурные логи с request_id, сквозным через все слои.
- **Бэкапы:** PostgreSQL — ежедневный полный + WAL-архив, хранение 30 дней, ежемесячная проверка восстановления на тестовом окружении. S3 — версионирование объектов.

## 5. Структура API (`/api/v1`)

### Реализованный редактор E6B

Кабинет создаёт курс с нуля (первый пустой набор) либо из своего свободного набора.
`GET /courses/{id}/editor` возвращает структуру и revision;
`PUT /courses/{id}/structure` атомарно заменяет структуру по revision и Idempotency-Key.
Существующие статьи сохраняют set_id и ID при переносе; новые связывают свой свободный набор
или создают пустой. Пропущенные статьи/разделы удаляются после подтверждения в интерфейсе,
но наборы и учебный прогресс остаются. Опубликованный курс сначала снимается с публикации.
Технические пределы: 50 разделов, 100 статей, 100 000 символов на статью, 1 млн на курс.

`POST /courses/{id}/copy` с необязательным article_id создаёт независимый приватный курс
(при article_id — только выбранную статью). Копируются теория, карточки со всеми вариантами
ответов и собственные медиа нового владельца. Прогресс и публикация не копируются. Доступ
проверяется к своему либо опубликованному доступному оригиналу. Повтор с тем же ключом
не создаёт вторую копию. После закрытия оригинала существующая копия остаётся у владельца.

Общий рендерер теории поддерживает заголовки, жирный текст, списки, inline-код и блоки кода
без исполнения HTML и загрузки внешних ресурсов. Страница чтения имеет оглавление,
предыдущую/следующую статью и ссылки на обучение по её набору. История версий и откат
автору не добавляются; сохранения связанных оригиналов остаются задачей E6A.

## 7. Нефункциональные требования

### Отдельный срез: доступ внешнего ИИ-агента

Личный кабинет выдаёт персональный токен с названием, сроком, правами чтения/изменения
материалов и отдельным правом публикации. Полный секрет показывается однократно,
в базе хранится хеш; владелец видит последнее использование и может отозвать токен.
Токен не даёт доступ к API аккаунта и не заменяет JWT браузера.

JSON API позволяет читать, создавать и обновлять свои наборы и курсы целиком:
курс → раздел → статья с текстом теории → один набор карточек. Новые материалы приватные.
Каждая запись атомарна и идемпотентна по ключу запроса, обновления требуют текущую revision.
Существующие ID сохраняются; замена списка карточек удаляет пропущенные карточки,
но неявное удаление статей/разделов запрещено. История версий/откат не добавляются.
Опубликованный курс агент изменяет только после отдельного снятия с публикации.
Отдельный контракт структуры позволяет менять теорию и порядок без перезаписи карточек.
Удаление статьи/раздела требует явной операции с подтверждением и актуальной revision;
связанные наборы и прогресс остаются. Курс или отдельную статью можно независимо скопировать
из своего или публичного курса; копия приватная, без переноса прогресса.

MCP-коннектор использует тот же API. Генерацию из источников выполняет внешний агент
по готовому навыку; модель внутри Remora, загрузка исходных PDF и медиа через MCP
в этот срез не входят. Технический контракт: [07-agent-api.md](07-agent-api.md).

### Общие требования

Первый срез ботов Telegram/VK: обязательная привязка существующего аккаунта по одноразовому
коду из кабинета, личные сообщения, статус и отзыв. Отдельный внутренний bot-api не входит
в публичный router. Приём событий с проверкой секретов, долговечная очередь и дедупликация;
адаптеры не имеют доступа к БД. Подробности и оставшийся объём: [08-bots.md](08-bots.md).
