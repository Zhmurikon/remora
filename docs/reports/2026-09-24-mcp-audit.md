# Проверка MCP Remora — 24 сентября 2026

Запрос: проверить проблемы публикации курсов/карточек, исправить MCP и закрепить правила
содержания в коннекторе и навыке. Исправления коннектора и навыка находятся в отдельном
репозитории интеграций; серверное приложение в рамках задачи не развёртывалось.

## Подтверждённые дефекты и исправления

1. **Устаревший запуск в Codex и Claude Desktop.** Оба клиента ссылались на удалённый
   `apps/api/app/mcp_server.py`. Команда заменена на `uv run --frozen --env-file … --directory
   …/integrations/remora-ai-integrations/mcp-server remora-mcp`. Остальные настройки сохранены.
   После исправления оба запуска прошли initialize/list_tools и чтение API, доступны 16 инструментов.
2. **Потеря причины ошибки.** MCP заменял все отказы общим перечнем HTTP-статусов.
   Теперь передаёт `code`, ограниченное сообщение и диагностические поля `required_scope`,
   `reason`, `limit_key`, `max_size_bytes`, `errors[].loc/type`, числовой Retry-After.
   PAT маскируется; сырой ответ прокси, неизвестные детали, `input` и `ctx` не отражаются.
   Некорректный JSON успешного ответа сообщает о неизвестном результате записи и сохранении ключа.
3. **Ложное обещание приватности.** initialize-инструкция и create_set/create_course называли
   создаваемые материалы приватными. Исправлено: наборы публичны, включая наборы черновика курса;
   публикация курса — отдельная операция. Снятие публикации курса не закрывает наборы.
4. **Молчаливое отбрасывание полей.** Вложенные карточки, структура, копирование и публикация
   теперь отклоняют неизвестные поля в MCP. Это предотвращает ложное впечатление, что
   `visibility`, `audio` или неверно переданный `material` сохранены. API-контракт не расширялся.
5. **Поздние ошибки входных аргументов.** Ограничения offset/limit и Idempotency-Key теперь
   доступны в схеме MCP и проверяются до HTTP; проверены символы токена и порт origin.

Точную причину прежнего отказа конкретной публикации установить без исходной ошибки нельзя.
Обнаруженные дефекты воспроизведены независимо; исправления не означают, что все прежние
отказы были вызваны одним из них.

## Правила содержания

В MCP initialize-инструкции закреплены работа по источникам, проверка фактов, одна проверяемая
мысль на карточку, однозначность обеих сторон, отсутствие дублей и выдуманных ссылок,
качество неверных ответов, требования к теории, поддерживаемая разметка и размеры.
В навыке уточнены приватность, диагностика публикации, причины 409, сохранение ключей,
не более двух одинаковых повторов при временном сбое и проверка результата чтением.

Технические ограничения проверяются схемой/API. Достоверность фактов, качество объяснений
и учебная полнота — требования к агенту и редакционная проверка; схема JSON их не доказывает.
Семантическое качество генерации разных моделей в этом прогоне не измерялось.

## Дополнение по пользовательским скриншотам

Первичный прогон не покрывал HTML-подобные плейсхолдеры и точную сохранность всех текстовых
полей. Скриншоты позволили добавить конкретные регрессии.

**Угловые скобки — подтверждено.** `ContentService.sync_cards` вызывает HTML-проверку только
для `term` и `definition` при типах text/latex. `<package>`, `<T>` и те же строки в Markdown
backticks отклоняются с 409 ещё при сохранении; создание всего курса откатывается.
`content_type=code` вместе с `code_language=bash/cpp/html/text` сохраняет исходный синтаксис.
Этот запрет не применяется к `body` статьи. Менять смысл команд или заменять скобки во всём
payload не нужно.

MCP теперь повторяет эту проверку до HTTP и сообщает путь до карточки и допустимый формат.
Отсутствие языка у code также выявляется до сети. В навыке приведён готовый пример
`pip install <package>` и объяснены различия карточки, статьи, исполняемого HTML и учебного кода.
Backend-правило не менялось; добавлен тест его поведения и атомарности.

**Повреждённая кириллица — причина пока не установлена.** Текст на скриншоте похож на
ошибочное декодирование UTF-8 в однобайтовой кодировке, но скрин не показывает исходные байты.
В аккаунте доступного локального PAT другие названия: набора со скриншота нет. Эти названия
читаются правильно; HTTP отдаёт application/json и клиент декодирует его как UTF-8.
Поэтому нельзя утверждать, что повреждение происходило именно в MCP, API или браузере.

Добавлены проверки точного равенства кириллицы, ё, эмодзи и иероглифов в названиях,
описаниях, разделах, статьях и карточках. Проверены MCP stdio → HTTP (включая
PYTHONIOENCODING=cp1251), API → PostgreSQL → GET → публикация → публичный GET,
обычный UTF-8 JSON и JSON с экранированием Unicode. Искажение не воспроизвелось.
В навык добавлены правила UTF-8, проверка читаемости до записи, сравнение полей после записи,
остановка при искажении и запрет угадывать перекодировку для всей библиотеки.

Повторный прогон: **108 passed / 1 skipped** в MCP (необязательный live-тест отдельно
не повторялся в этом дополнении); **15 passed** в API (`test_agent_content_format.py`,
`test_agent_api.py`, `test_content.py`). Ruff, mypy коннектора и валидатор навыка прошли.
Это отдельный прогон: его число не следует складывать с первым как число уникальных тестов.
Тестовый стенд снова удалён. Рабочие материалы не редактировались.

Для завершения диагностики кириллицы нужны клиент/способ отправки, затронутый набор и
исходный JSON до отправки либо исходный текст. Секреты и заголовок Authorization не нужны.
Исправление повреждённых пользовательских данных не выполнялось и не объявляется завершённым.
