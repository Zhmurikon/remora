# Редакционный блог Remora

> Исторический отчёт о выпуске. Текущий публичный бренд — «Запоминальня»; старое имя и домен
> ниже сохранены как состояние на дату публикации.

Первый срез E6A: `/blog` и `/blog/{slug}` в `apps/web`. Блог отделён от статей
пользовательских курсов: публикует только редакция, материалы доступны без регистрации.

Опубликован 18.09.2026 из коммита `3903125`: https://test.edu-remora.ru/blog.
Список и три статьи проверены на сервере; тестовый контур по-прежнему закрыт от индексации.

## Публикация и редактирование

Новые материалы хранятся в `blog_posts` и создаются через административный агентский API.
`apps/web/src/content/blog.ts` остаётся bootstrap-копией стартовых статей: сайт объединяет её
с опубликованными записями API по slug, причём запись из API имеет приоритет. Одна публикация
содержит постоянный slug, статус, заголовок, описание, рубрику, даты, схему или обложку, разделы,
rich text, примеры, источники и ссылки на связанные публикации.

1. Администратор создаёт персональный токен с `blog:read` и `blog:write`. Для отдельной команды
   публикации добавляет `blog:publish`; все три права по умолчанию выключены.
2. Агент загружает нужные изображения через `/agent/blog/media`, создаёт черновик и перечитывает
   его. Короткие абзацы хранятся в `paragraphs`, сложная разметка — в `rich_text`.
3. Редактор проверяет факты, формулировки, источники, slug, alt-тексты и оглавление. Обновление
   передаёт документ целиком с актуальной целочисленной `revision`.
4. Только после явного решения пользователя агент вызывает `/publish` с отдельным правом.
   Содержательная правка опубликованного материала требует явного `/unpublish`, чтения новой
   revision, изменения и повторной публикации.
5. Список, статья, JSON-LD, архив и sitemap получают опубликованную запись серверным запросом.
   Пересборка фронтенда не нужна; кэш обновляется в пределах 60 секунд.

Черновики и будущие публикации не выдаются публичным селектором: их нет в списке,
статических маршрутах, SEO-метаданных, JSON-LD, связанных статьях и sitemap. Прямой адрес
возвращает 404. Публичного предпросмотра черновиков нет; для локального просмотра редактор
может временно менять статус в своей рабочей копии, не публикуя её.

Дата первой публикации назначается сервером и сохраняется при повторном выпуске. Встроенного
планировщика публикаций нет. Не хранить секреты ни в тексте, ни в источниках, ни в агентских
заданиях. Порядок — по дате публикации от новых к старым, при совпадении — по slug.

Визуальный административный редактор, отдельная роль редактора, комментарии, подписка,
автоматическая публикация по расписанию и поиск по блогу не входят в этот срез.

### Rich text

Поле `richText` рендерится на сервере тем же безопасным Markdown-рендерером, который
используется для теории курсов. Поддерживаются заголовки, абзацы и переносы, жирное и курсивное
начертания, зачёркивание, абсолютные `http(s)`- и `mailto`-ссылки, вложенные маркированные и
нумерованные списки, цитаты, таблицы, горизонтальные разделители, строчный и fenced-код,
формулы KaTeX и изображения. Стили также подготовлены для семантических подписей изображений,
определений, сносок, раскрывающихся и редакционных информационных блоков будущей CMS.

В статье уже есть единственный `h1`, поэтому Markdown-заголовок первого уровня становится
`h3`, второго — `h4`, а остальные ограничиваются уровнем `h6`. Таблицы и блоки кода получают
собственную горизонтальную прокрутку и не расширяют страницу на мобильном экране.

Сырой HTML отключён. Изображение допустимо только как `![Описание](media:UUID)`, а соответствие
UUID подписанному URL, ширине и высоте задаётся в карте `media` того же раздела. Внешний URL
из Markdown не превращается в изображение. У содержательных изображений обязателен осмысленный
alt-текст; декоративные изображения в тексте не используются.

## Содержание и оформление

Стартовые статьи: как выучить конспект, как создать карточки, как выучить билеты.
Авторство обозначено как «Редакция Remora», без выдуманных специалистов и показателей.
Тезис о самопроверке в статье про конспекты сопровождается ссылкой на исследование
Roediger & Karpicke (2006); конкретные шаги — редакционный практический сценарий,
не обещание гарантированного результата.

Дизайн продолжает главную: существующие токены двух тем, знак рыбы, просторная сетка,
одна крупная публикация и две обычные карточки. Обложки — лёгкие HTML-схемы без растра
и фоновой анимации. Статья: хлебные крошки, даты и примерное время чтения, оглавление,
колонка текста до 700 px, примеры, источники, демо и связанные материалы.
Время чтения — оценка по 180 словам в минуту, а не измеренное поведение пользователей.

## SEO и технические границы

- Полный статический HTML, без запросов к API и базы данных блога.
- Уникальные title, description и canonical; Open Graph `article` с датами и авторством,
  Twitter Card и существующая общая OG-картинка Remora.
- JSON-LD: `Blog`, `BlogPosting`, `Organization`, `BreadcrumbList`; безопасное экранирование.
- Sitemap включает только опубликованные статьи и реальные даты их обновления.
  Блог остаётся в карте при недоступном API курсов.
- Из главной добавлены ссылки в обычную/мобильную навигацию и подвал.
- Запрет индексации тестового окружения на gateway не изменяется.

API, права пользователей, схема OpenAPI и база данных не меняются. Тесты доступа
относятся к границе редакционной публикации: черновик, будущая дата и неизвестный slug
недоступны как через страницу, так и через метаданные.
